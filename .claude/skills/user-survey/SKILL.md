# /user-survey

prd.md のターゲットユーザーから多数のペルソナを生成し、設問に回答させて定量データを収集・統計サマリを作成する。

## Input（すべて読み込む）

- `docs/reqs/prd.md` — ターゲットユーザー、ペイン、提供価値
- `docs/reqs/product-model.json` — entities, actors, screens, transitions
- `docs/reqs/user-stories.md` — ストーリー（存在すれば）
- `docs/specs/ui-spec.md` — 画面定義（存在すれば）

## Output

アンケート結果の統計サマリをユーザーに提示する（ファイル出力はしない）。

## Execution Steps

### Step 1: 企画書を読み込む

prd.md と product-model.json は必須。存在しないかテンプレート状態の場合は中断する。

### Step 2: 設問を設計する

調査目的に応じた設問セットを作成する。ユーザーに調査したいテーマを確認する。

**設問の構成（目安 5〜10問）:**
- 5段階評価（リッカート尺度）: 3〜5問。「この機能に魅力を感じるか」「使いたいと思うか」等
- 選択式: 1〜3問。「最も重要な機能はどれか」「どの場面で使いたいか」等
- 自由記述: 1問。「率直な感想・懸念」

設問をユーザーに提示し、承認を得てから次へ進む。

### Step 3: 回答者の属性分布を定義する

prd.md のターゲットUser像をベースに、回答者の属性分布を設計する。

| 属性 | 分布例 |
|---|---|
| ロール | actors の比率に応じて配分 |
| ITリテラシー | 低20% / 中50% / 高30%（prd.md に応じて調整） |
| 利用頻度想定 | ヘビー20% / 通常60% / ライト20% |
| 年齢層 | ターゲットの中心±幅を持たせる |

**エクストリームユーザーを含める:**
- 全回答者の10〜15%をエクストリーム属性にする
- 利用頻度・スキル・環境・動機の極端なバリエーションを混ぜる

回答者数はユーザーに確認する（デフォルト: 100人）。

### Step 4: survey-respondent エージェントを並列起動する

回答者を10〜20人単位のバッチに分け、survey-respondent エージェントを並列起動する。

Agent ツールで `.claude/agents/survey-respondent.md` を指定し、prompt に以下を含める:
- バッチ内の回答者属性リスト（名前は不要。属性の組み合わせのみ）
- 設問セット
- プロダクト概要（prd.md の提供価値・機能概要を要約）
- 画面・操作フローの要約（ui-spec.md または product-model.json の screens から）

### Step 5: 回答を集計・統計サマリを作成する

全バッチの回答を統合し、以下の形式で整理する。

```markdown
## アンケート調査結果

**実施日:** {日付}
**回答者数:** {N}人
**調査テーマ:** {テーマ}

### 回答者属性

| 属性 | 内訳 |
|---|---|
| ロール | {分布} |
| ITリテラシー | 低{n}% / 中{n}% / 高{n}% |

### 設問別集計

#### Q1: {設問}（5段階評価）

| 評価 | 人数 | 割合 | ████████ |
|---|---|---|---|
| 5（強く同意） | {n} | {%} | {棒グラフ} |
| ... | | | |

**平均:** {値} / **中央値:** {値}

**属性別クロス集計:**
| 属性 | 平均 | 特記 |
|---|---|---|
| ITリテラシー高 | {値} | {差異があれば} |

#### Q{n}: {自由記述設問}

**頻出キーワード:** {キーワードと出現数}
**代表的な回答:**
- ポジティブ: 「{回答}」（{属性}）
- ネガティブ: 「{回答}」（{属性}）

### 総括

- **強いシグナル:** {統計的に明確な傾向}
- **注意シグナル:** {評価が割れている項目、属性による差異}
- **深掘り推奨:** {/user-test や /user-interview で掘るべきテーマ}
```

## 注意

- 設問は調査目的に集中させる。関係ない設問を入れない
- 回答のバラつきはペルソナ属性の違いから自然に生まれるべき。意図的に偏らせない
- 統計サマリは事実ベースで記述する。過度な解釈を加えない
- 「深掘り推奨」で /user-test・/user-interview への接続を示す
