# /test-run

`docs/specs/test-spec.md` に基づいて実装の検証を行う。

## 前提確認

1つでもNoならユーザーに報告して中断する。

- `docs/specs/test-spec.md` が存在し、内容が記述されているか
- テスト対象の実装が完了しているか

## Execution Steps

### Step 1: Specs整合性テスト（test-spec セクションA）

test-spec.md のセクションAに定義された項目を上から順に実行する。

1. DB Schema整合性 — テーブル定義と照合
2. API整合性 — 全エンドポイントに正常系/異常系リクエスト
3. 認証・認可整合性 — 認証フロー、ロール別許可/拒否
4. UI整合性 — 全画面パス、状態表示、フォームバリデーション

**遷移判断:**
- Failが0件 → Step 2に進む
- DB/API/AuthにFail → 中断して報告
- UI のみFail → Step 2に進む（Failは報告に含める）

### Step 2: シナリオテスト（test-spec セクションB）

優先度順に実行する。

1. Must（正常系 → エッジケース）
2. Should（正常系のみ）
3. Could（スキップ可）

### Step 3: レポート出力

```
## テスト実行レポート
### サマリー
- Specs整合性: N Pass / N Fail
- シナリオテスト: N Pass / N Fail
### Fail分類
| # | テスト項目 | 分類 | 説明 |
|---|---|---|---|
| 1 | [項目] | 実装バグ / Spec不備 / 新規エッジケース | [詳細] |
### 推奨アクション
- 実装バグ: [修正対象]
- Spec不備: [修正が必要なSpec]
- 新規エッジケース: [追加候補]
```

## 注意

- テスト実行中にSpecや実装の修正はしない。Failとして記録し報告する
- 推奨アクションは提案のみ。実行はユーザーの指示を待つ
