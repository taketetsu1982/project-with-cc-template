# /user-interview

prd.md のターゲットユーザーから1人のペルソナを生成し、ユーザー（人間）がそのペルソナに自由に質問できる対話セッションを開始する。

## Input（すべて読み込む）

- `docs/reqs/prd.md` — ターゲットユーザー、ペイン、提供価値
- `docs/reqs/product-model.json` — entities, actors, screens, transitions
- `docs/reqs/user-stories.md` — ストーリー（存在すれば）
- `docs/specs/ui-spec.md` — 画面定義（存在すれば）

## Execution Steps

### Step 1: 企画書を読み込む

prd.md と product-model.json は必須。存在しないかテンプレート状態の場合は中断する。

### Step 2: ペルソナを選択する

ユーザーに以下を確認する:

1. **ロール**: actors のどのロールか
2. **属性の方向性**: 以下から選択またはカスタム指定
   - 典型的なユーザー
   - ITリテラシーが低いユーザー
   - ヘビーユーザー
   - エクストリームユーザー（具体的な軸を指定）
   - カスタム（自由に属性を指定）

指定がなければ、prd.md のメインターゲットに最も近い典型的なペルソナを1人生成する。

ペルソナ定義:

| 項目 | 内容 |
|---|---|
| 名前 | 架空の日本語名 |
| 年齢・職業 | prd.md のターゲットUser像に基づく |
| ITリテラシー | 低 / 中 / 高 |
| 利用シーン | prd.md の主な利用シーンから具体化 |
| 抱えている課題 | prd.md のUserのペインから具体化 |
| 性格・行動傾向 | 慎重派 / せっかち / 探索好き など |
| このプロダクトへの期待 | 提供価値に対する具体的な期待 |
| エクストリーム属性 | 該当する場合のみ |
| 日常で使っているツール | ITリテラシーから推測した具体例 |
| 過去の類似体験 | 競合製品や代替手段の利用経験 |

### Step 3: interviewee エージェントを起動する

Agent ツールで `.claude/agents/interviewee.md` を指定し、prompt に以下を含める:
- ペルソナ定義（Step 2 で生成したもの）
- プロダクト概要（prd.md の提供価値・機能概要を要約）
- 画面・操作フローの要約（ui-spec.md または product-model.json の screens から）

エージェント起動後、ユーザーに以下を伝える:

```
{ペルソナ名}（{年齢}・{職業}）とのインタビューを開始します。
自由に質問してください。終了するときは「インタビュー終了」と入力してください。
```

### Step 4: 対話を中継する

ユーザーの質問を interviewee エージェントに SendMessage で転送し、回答をユーザーに返す。
「インタビュー終了」が入力されるまで繰り返す。

### Step 5: インタビューサマリを作成する

対話終了後、やり取りの内容を以下の形式で要約する。

```markdown
## インタビューサマリ

**実施日:** {日付}
**ペルソナ:** {名前}（{ロール}・{年齢}・ITリテラシー{高/中/低}）

### 主要な発見

- {発見1: ペルソナが強く反応したポイント}
- {発見2}

### ペルソナの態度

| 観点 | 態度 | 根拠となる発言 |
|---|---|---|
| プロダクトへの関心 | 高/中/低 | 「{発言抜粋}」 |
| 現状の課題の深刻度 | 高/中/低 | 「{発言抜粋}」 |
| 乗り換え意欲 | 高/中/低 | 「{発言抜粋}」 |

### 示唆

- {企画・設計への示唆}
```

## 注意

- ペルソナは prd.md の定義から逸脱しない
- product-model.json にない機能については「知らない」と答えるのが自然
- インタビュアー（ユーザー）の質問を誘導しない。聞かれたことに答える
- 同じペルソナで複数回インタビューする場合、前回の文脈は引き継がない（毎回新規）
